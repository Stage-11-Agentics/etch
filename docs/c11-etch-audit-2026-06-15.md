## Executive verdict

**Etch is working correctly on c11, and its worktree handling is better than my first pass credited — but the pilot was under-capturing badly for a reason that wasn't Etch's design: a stale binary.** `doctor` is green across every check, the public-repo posture is exactly right (no push refspec on any remote, salt stays in local `.etch/settings.json`), and live Claude capture keeps pace with real Claude activity. Worktrees **do** capture — operator mode stamps every worktree's `settings.local.json` (12/12 stamped Jun 12), and two of the 13 captured sessions provably originate from worktree paths on branches with no committed hooks. The two recon scares resolve benignly: the "3 wip leftovers" were **crash buffers recovery has since sealed into `incomplete` refs**, and the low session count is explained by the deployed binary predating the `import` path. A dry-run finds **188 importable sessions: 126 Claude (pre-rollout history) + 62 Codex.** The Codex slice is the structurally-significant one — Codex has no live-hook surface, so *every* Codex session is import-only, and all 151 c11-cwd Codex rollouts on disk launched with yolo/danger sandbox flags referencing c11/computer-use/review (i.e. they're automation-driven: clear-codex reviews, the computer-use harness, upstream-triage — not interactive operator use, which is why the volume is surprising). That binary has now been upgraded; running `import` converts the pilot from live-Claude-only to true every-session coverage. Nothing is silently degrading under load; the gap was capability-not-installed, now fixed.

### 4. Fleet / clone coverage — *corrected: worktrees capture via the stamp*

Coverage does **not** hinge on committed hooks: it hinges on the **operator-mode stamp** (`.claude/settings.local.json`), which the `post-checkout` hook writes into every worktree and which `etch enable` set repo-wide. The stamp's hooks carry a dedupe guard (`if grep -qs entire-agent-etch .claude/settings.json; then exit 0`) so they yield to committed hooks where present and fire themselves where not. **Root cause of the gap: the deployed binary predated the `import` path — not cold start, not leakage.** The pilot's installed binary (built Jun 12 16:26) shipped *before* PR #10 "Two-path ingestion." Live Claude hooks worked, so recent Claude sessions captured fine. The 188 split: **126 Claude** are pre-rollout history (capture turned on Jun 9, so anything before is import-only) and **62 Codex** — and Codex is the structurally interesting half, because **Codex exposes no usable live-hook surface** (only a coarse `notify`), so the *only* way Etch ever captures Codex is `import`. With import missing from the binary, every Codex session was invisible and `capture.method` provenance (which would have flagged "Codex coverage is zero") was absent too. **Why so much Codex when the operator rarely drives it interactively:** all 151 c11-cwd Codex rollouts launched with yolo/danger sandbox flags and reference c11/computer-use/review — they're automation (clear-codex reviews, the `codex --yolo` computer-use harness, upstream-triage), not hand-driven sessions. The `2564 out-of-repo` are other repos' transcripts, correctly excluded; `0 failed` means the parser handles the whole corpus cleanly.

**Fix applied:** binary rebuilt + reinstalled from source mid-audit. `import` now exists; running it backfills the 188 (idempotent, dedupe on `agent_session_id`, hooks always win). Pending operator go-ahead — it's a one-time bulk write of immutable refs.

## Recommendations

1. **Run the `import` backfill (≈188 sessions: 126 Claude + 62 Codex).** *Now unblocked* — binary upgraded. `entire-agent-etch import` (no `--dry-run`) recovers the backlog into refs, idempotently. The 62 Codex are the high-value half (otherwise permanently uncaptured); the 126 Claude are pre-rollout history. Confirmed real c11 work (automation-driven Codex + pre-rollout Claude), correctly repo-attributed. One-time bulk write of immutable refs; reversible by ref deletion. **Pending operator go-ahead.**

2. **Do *not* merge committed hooks into feature branches.** *This reverses my first-pass rec.* Worktrees already capture via the operator-mode stamp (Section 4), so the merge buys zero coverage — and committing hooks onto live branches reintroduces exactly the branch-entanglement operator mode was built to eliminate (`docs/ENABLEMENT.md`). Dedupe means it wouldn't double-capture, but it's the wrong lever. Leave the feature branches alone; the stamp has them covered.

3. **Keep the upgraded binary current going forward.** The whole gap was a stale install (built before the `import`/provenance release). Rebuild + reinstall (`make install PREFIX=$HOME/.local`) after landing capture changes. *Product gap to file: `doctor` should report build version/date and warn when the installed binary lags source — so "binary is stale" is a visible check, not something an audit trips over.* (Now in ROADMAP.md.)

4. **`c11-private` is uncovered but low-stakes** — separate clone, no `.claude/` config, zero transcripts. If agent work ever moves there, `entire-agent-etch enable`. No action today.

5. **Minor:** consider setting `recovery_timeout_hours` explicitly in `.etch/settings.json` (vs the 4h default) for a high-traffic pilot where parallel-agent crashes are routine (the Jun-14 burst left 3). Early-crash sessions still land with `model: null` / no prompt — capturing model at `session_start` before the first crash-prone tool call would reduce null fields.

6. **Consumption layer (the open question).** How the operator reads this substrate — agent-mediated query (today), generated digests into a browsable wiki, or a downstream dashboard — is now framed in ROADMAP.md. Philosophy is clear that all three are *downstream consumers* of the honest record, never folded into capture.
