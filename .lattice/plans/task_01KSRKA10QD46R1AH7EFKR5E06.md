# ETCH-12 Plan — Lattice orchestrator skill exports CAIRN_* env vars

## Goal

Make Etch's orchestration capture work end-to-end: the lattice-orchestrator skill
must export the `CAIRN_*` env-var contract (OUTPUT_SPEC §3) into every delegator /
sub-agent boot prompt. Without this, every orchestrated session captures
`orchestration.type == "manual"` — wrong for delegators.

Work splits across two repos:
- **c11 repo** (authoritative skill source) — the load-bearing change.
- **Etch repo** (this worktree, `feat/etch-12-skill-env`) — marker doc + Go tests
  proving `CaptureOrchestration()` reads the exact contract the skill exports.

## Findings (pre-work investigation)

- Skill source of truth: `code/c11/skills/lattice-orchestrator/{SKILL.md,references/orchestrator.md}`.
  The install at `~/.claude/skills/lattice-orchestrator/` is a **copy, not a symlink**
  (different sizes/mtimes) — but the ticket scope says edit the source in the c11 repo
  and commit there. The installed copy is regenerated by c11's skill install flow; we
  do not hand-edit it.
- `references/orchestrator.md` has three boot-prompt templates, each with a
  `## Environment` block containing `export LATTICE_ROOT=...`:
  - Fast-track (line ~351)
  - Inline-full (line ~391)
  - Sub-agent-full (uses an atomic launch line `export LATTICE_ROOT=$REPO_ROOT`, no
    standalone `## Environment` block — handled via its launch-line + boilerplate).
- Etch capture: `internal/capture/environ.go::CaptureOrchestration()` reads 6 of the 8
  vars into the `Orchestration` struct (type, dispatch_method, ticket_id, run_id, role,
  workflow_version) plus `CAIRN_ORCHESTRATION_EXTRA` → `Extra` map.
  `CAIRN_PARENT_SESSION_ID` is NOT part of `Orchestration` — it is consumed at the
  hook layer (`internal/hooks/session_start.go:74`) and set on the top-level
  `Session.ParentSessionID`. So the "all 8 vars" test sets all 8 but asserts the 6
  orchestration fields + extra; parent-session capture is exercised by existing hook
  tests, noted in the test comment.
- Schema: `internal/schema/session.go::Orchestration` — `Type` (string, default
  "manual"), the five `*string` ptr fields, `Extra map[string]any`.
- Existing tests `TestCaptureOrchestrationDefaults` / `TestCaptureOrchestrationWithEnv`
  already cover the basics; the four mandated tests are sharper, explicitly-named
  variants that pin the skill-export contract.

## Changes

### c11 repo — `references/orchestrator.md`
1. Add a HARD RULE subsection in the sub-agent boilerplate area:
   **"### Export CAIRN_* env vars before launching any sub-agent (orchestration capture)"**
   — the full contract block from the ticket, with the "absent → manual" note and a
   pointer to `code/Etch/OUTPUT_SPEC.md §3`.
2. Insert the `CAIRN_*` export block into each boot template's `## Environment` block,
   immediately after `export LATTICE_ROOT=...`:
   - Fast-track → role `delegator`, dispatch `c11_delegator`.
   - Inline-full → role `delegator`, dispatch `c11_delegator`.
   - Sub-agent-full → add an `## Environment` block to the delegator boot + note that
     each sub-agent spawn line additionally exports `CAIRN_AGENT_ROLE` (planner/impl/
     reviewer/fix) and `CAIRN_PARENT_SESSION_ID`.
3. Extend the atomic-cwd-binding launch-line HARD RULE to carry the per-sub-agent
   `CAIRN_AGENT_ROLE` + `CAIRN_PARENT_SESSION_ID` alongside `export LATTICE_ROOT`.
Commit + push in the c11 repo on its current branch. Capture the SHA.
