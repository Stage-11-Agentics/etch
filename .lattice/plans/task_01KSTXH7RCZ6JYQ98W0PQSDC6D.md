# ETCH-16: setup-refspec silently breaks normal 'git push' (pushes only etch refs, not your code)

Naive flow: ran 'entire-agent-etch setup-refspec' as README Configure says, set origin URL, then ran a plain 'git push origin'. RESULT: only refs/etch/sessions/* were pushed; my 'master' branch (the actual code) did NOT land on the remote — git reported success. CAUSE: setup-refspec adds an explicit 'remote.origin.push refs/etch/sessions/*:refs/etch/sessions/*' entry, which overrides git's default branch-push behavior, so 'git push' now pushes ONLY etch refs. EXPECTED per README ('per-session refs sync with your remote'): etch refs sync IN ADDITION to my normal push, not instead of it. A real user will push, see success, and not realize their commits never left the machine. README/equivalent-manual-config reproduce the same trap and give no warning. Fix idea: also add a branch push refspec, or use a push option that augments rather than replaces default, or loudly document the side effect.
