# ETCH-20: Hook-event JSON contract is undocumented; wrong field names are silently dropped

Because auto-dispatch doesn't work on Entire v0.6.3 (see ETCH-17), the only way to verify capture is to hand-feed hook events to the binary. But the README documents neither the event field names nor an example payload — it only says etch 'consumes the exact hook contract Entire dispatches.' Guessing reasonable names, I sent session_start with top-level {"model":"..."} and user_prompt_submit with {"prompt":"..."}. RESULT: session.json had agent.model=null and prompt.text="" — data silently dropped, no warning, exit 0. The ACTUAL fields (found in scripts/smoke.sh) are raw_data.model and user_prompt. With those, capture is perfect. So the binary is correct; the gap is (a) no documented event schema and (b) silent dropping of unrecognized fields. Recommendation: document the event payload contract in README/OUTPUT_SPEC, and/or warn when expected fields are absent.
