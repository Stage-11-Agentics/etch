# ETCH-37: README claims 'salted hash' for hostname but implementation is unsalted SHA-256

AUDIT ITEM 7 (doc audit) + SPEC #7. README.md line ~107: 'the hostname is stored as a salted hash.' ACTUAL: capture/machine.go uses sha256.Sum256([]byte(hostname)) with NO salt (grep 'salt' -> none). OUTPUT_SPEC.md says only 'SHA-256 of hostname'. Two problems: (1) README is factually wrong ('salted'). (2) An UNSALTED hash of a low-entropy hostname (e.g. 'Hyperion', 'Atlas') is trivially reversible by brute force/rainbow table, so the privacy protection is weak -- and identical across repos/machines, enabling correlation. FIX: either add a real per-repo salt and keep the 'salted' claim, or correct the README to 'SHA-256 hash' and document the reversibility limitation.
