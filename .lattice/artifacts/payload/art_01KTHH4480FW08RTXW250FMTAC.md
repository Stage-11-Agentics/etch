# Code Review: ETCH-41 — `local_only_fields` strip-before-push transport

## 1. Verdict

**FAIL (implementation-level)**

The ETCH-41 implementation itself is correct, faithful to the authoritative plan, and validated end-to-end — I would PASS it on its own merits. The single reason for a FAIL is integration: the branch is cut from **pre-#21 main** and produces real merge conflicts against current `main`, so it cannot land under the "auto-merge through to done" policy without a rebase, and it has never been compiled/tested against the `agent_session_id` field that #21 added. The required rework is mechanical (rebase + one conscious skip-list decision + re-run gates), not a redesign.

## 2. Summary

ETCH-41 implements write-time projection: when `local_only_fields` is configured, the commit boundary writes the full record to a never-pushed `refs/etch/local/<ULID>` first, then a stripped projection to the canonical `refs/etch/sessions/<ULID>`. The strip walker, dual-ref logic on both the normal and crash-recovery paths, commit-message/trace leak mitigations, required-field skip-list, and documentation are all implemented cleanly and exactly match the plan's Cycle-1 resolutions (R1–R6). `go build ./...` is clean and `go test ./...` is fully green, including a genuine transport gate (bare remote → `git push` → fresh clone) that proves the core promise. The only blocker is that the branch is based on pre-#21 main and conflicts with current `main`.

## 3. Issues

**[MAJOR] (whole branch) — Branch is based on pre-#21 main; merges with conflicts and was never integrated against `agent_session_id`**
Merge-base with `main` is `3dc67d4` (before PR #21, `9df6aa7`). Current `main` adds `agent_session_id`, `tokens: null`, and the hostname salt — all of which touch the same files ETCH-41 edits. `git merge-tree main feat/local-only-transport` reports `changed in both` / conflict markers in `OUTPUT_SPEC.md` and `README.md` (and the `schema.Session` struct gained a field near the top). Two concrete consequences:
1. The auto-merge-through-to-done policy will stall on conflicts in the docs.
2. The strip skip-list (`requiredPaths` in `internal/redact/strip.go:61`) predates `agent_session_id`. After rebase, `agent_session_id` will be a strippable field not on the skip-list. That is *defensible* (it is nullable, not an OUTPUT_SPEC-required field, so leaving it user-strippable is a reasonable default), but it should be a conscious decision made against the merged schema, not an accident of branching order. The ticket itself says "land AFTER that batch" — that ordering needs to be honored by rebasing.
**Fix:** Rebase `feat/local-only-transport` onto current `main`, resolve the `README.md` / `OUTPUT_SPEC.md` conflicts (both #21's `tokens: null` / `agent_session_id` prose and ETCH-41's Privacy section must survive), confirm `schema.Session` carries both `AgentSessionID` and `LocalOnlyStripped`, decide explicitly whether `agent_session_id` belongs on the skip-list (recommend: no — keep it strippable, but document it), then re-run `go test ./...`, `make build`, `make smoke` on the rebased tree.

**[MINOR] internal/hooks/commit.go:51-52 — Self-heal "identical orphan SHA" comment over-claims for the normal-path crash window**
The comment states a crash between the `local/` and `sessions/` writes self-heals because "identical content yields the same orphan SHA," making recovery's rewrite an `update-ref` no-op. That holds for two *recovery* runs, but if the crash occurs in the **normal** path (after the `local/` write), the original `local/` ref was built from the capture-derived `sessionJSON`/`buildRefMeta`, whereas recovery rebuilds it from the reconstructed `*schema.Session`/`buildRefMetaFromSchema`. Those can marshal differently (struct shape, timing fallback), so recovery may write a *new* SHA and orphan the old commit rather than no-op. The end state is still correct (update-ref overwrites; the stray orphan is GC-eligible), so this is a comment-accuracy nit, not a correctness bug.
**Fix:** Soften the comment to "recovery re-commits both refs and the canonical `sessions/` ref converges; any orphaned partial `local/` commit is overwritten or GC'd" — drop the "same SHA / no-op" guarantee for the cross-path case.

**[MINOR] internal/hooks/commit.go:46 — Redundant `local/` ref when configured paths strip nothing**
When `len(LocalOnlyFields) > 0` but no path actually matches (all no-ops / already-zero), a `local/` ref is still written and the `sessions/` ref carries no `local_only_stripped` manifest (it's `omitempty`). The two refs then hold equivalent data, costing an extra ref/commit per session with no privacy benefit. Harmless but slightly wasteful at the 60–80-agent scale this project targets.
**Fix:** Optional — gate the `local/` write on `len(applied) > 0` by computing the strip first, or accept it as negligible. Not blocking.

## 4. Positive Observations

- **The transport gate is real, not a mock.** `TestE2ELocalOnlyTransport` (`internal/hooks/local_only_test.go:230`) spins up a bare remote, runs `setup-refspec`, captures a session with a secret in a configured field, does a *bare* `git push`, then clones to a second dir and fetches — asserting the secret never reaches the remote or clone, the marker is present, `refs/etch/local/` exists nowhere off-machine, and full fidelity survives locally. This directly exercises the core promise ("a bare `git push` must not leak") against git's actual transport, which is exactly the right gate.
- **Safety is by construction.** `setup_refspec.go` only ever names `refs/etch/sessions/*`; the `local/` namespace is never in any refspec. The write-time design means stale/hand-written refspecs cannot leak — the rationale in plan §2 is sound and the code honors it.
- **Leak vectors beyond the JSON body were caught and closed.** The pushed ref's `agent-trace.json` and commit message are both regenerated from the *stripped* `*schema.Session` (`stripForPush`, commit.go:125), and `TestE2ELocalOnlyDualRef` independently asserts the trace and commit message don't leak `files_touched` / branch. This is the subtle part most implementations miss; it's handled correctly on both the normal and recovery paths.
- **Strip walker is well-factored and correct.** `strip.go` shares `walk.go`'s reflection idioms without duplicating the exhaustive traversal (honoring the R6 resolution), handles `*string`→marker vs non-string→zero/null, implicit array fan-out, `orchestration.extra` map-key/interface-boxed descent, prefix-based protected-path logic (`isProtectedPath`, strip "agent" blocked but "agent.model" allowed), dedup + `TrimSpace`, and idempotence. The 15 unit tests in `strip_test.go` cover each of these including round-trip schema validity.
- **Zero-behavior-change default is enforced and tested.** `TestE2ELocalOnlyEmptyConfigNoChange` proves the empty-config path produces the full record in `sessions/` and *no* `local/` namespace at all — minimal blast radius.
- **Docs are thorough and accurate.** README Privacy section, the settings entry, and OUTPUT_SPEC (schema field + git-layout diagram) all describe the two-namespace reality precisely, including the deliberate local-query trade-off (R2c) and the wildcard-refspec warning.
